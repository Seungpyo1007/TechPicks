## 프롬프트 (여기부터 복사)

너는 **TechPicks v2**의 프로덕트 디자이너다. 전자기기 스펙을 찾고, 비교하고, AI에게 추천받는 Flutter 모바일 앱(Android/iOS)의 디자인 시스템과 핵심 화면을 설계해줘.

### 1. 무엇을 만드는가

TechPicks는 스마트폰·CPU·GPU·노트북의 스펙과 성능 점수를 비교해 구매 결정을 돕는 앱이다. v1은 제품 4개가 코드에 하드코딩돼 있었지만, v2는 **9만 3천 대의 스마트폰과 4천 개의 CPU**를 실제 데이터셋(TechAPI)에서 받아온다. 그래서 v2의 디자인 과제는 "예쁜 카드 만들기"가 아니라 **대규모 카탈로그를 탐색 가능하게 만드는 것**이다.

### 2. 사용자와 상황

- 새 기기 구매를 앞두고 두세 후보를 좁히는 사람
- 스펙 용어(SoC, nm 공정, nits)를 다 알지는 못하는 일반 소비자
- 한국어/영어 사용자 (앱은 ko-KR / en-US 지원)
- 이동 중 한 손으로, 밝은 실외와 어두운 실내 양쪽에서 사용

### 3. 브랜드 — 상위 조직과 맞춘다

TechPicks는 `GetTechAPI` 생태계의 클라이언트 앱이다. 상위 프로젝트(TechAPI)가 이미 쓰는 토큰을 **그대로 계승**한다. 새로 만들지 말 것.

```
악센트    민트    #3ce0b0 (다크) / #0f9e7a (라이트, 텍스트용)
악센트 위 텍스트  #04130d
서체      Space Grotesk (sans) / JetBrains Mono (수치·스펙값)
라운드    4px  ← 작다. 둥글둥글한 카드가 아니라 각진 기술 문서 톤
```

| 역할 | 다크 | 라이트 |
|---|---|---|
| bg | `#0a0a0b` | `#f6f6f1` |
| surface | `#111114` | `#ffffff` |
| surface-2 | `#17171b` | `#f0f0ea` |
| surface-3 | `#1d1d22` | `#e8e8e1` |
| border | `#26262c` | `#e2e2da` |
| border-strong | `#3a3a44` | `#cfcfc4` |
| fg | `#f4f4f0` | `#0c0d0a` |
| fg-2 | `#c7c7cc` | `#3a3b36` |
| muted | `#84848e` | `#6c6d66` |
| faint | `#56565e` | `#9a9b92` |
| warn | `#ffc24b` | `#b06d00` |
| err | `#ff6b7d` | `#d62f45` |

**다크 모드는 라이트의 반전이 아니라 각각 선택된 값이다.** 위 표대로 쓸 것.

> 참고: v1은 로그인 화면에 Rive 로봇 애니메이션, 검정→파랑 그라디언트, 흰 알약 버튼을 썼다. 이 톤은 위 브랜드와 충돌한다. **v1 비주얼은 계승하지 않는다.**

### 4. 실제 데이터 형태

상세 화면 하나가 받는 JSON은 이렇다. 이 필드들이 화면에 어떻게 앉을지가 설계의 핵심이다.

```json
{
  "slug": "galaxy-s25", "name": "Galaxy S25",
  "brand": { "slug": "samsung", "name": "Samsung", "country": "KR" },
  "soc": { "name": "Snapdragon 8 Elite", "manufacturer": {"name": "Qualcomm"},
           "process_nm": 3.0, "gpu_name": "Adreno 830" },
  "release_date": "2025-02-07", "msrp_usd": 799,
  "ram_gb": 12, "storage_options_gb": [128, 256, 512],
  "display": { "size_inch": 6.2, "resolution": "2340x1080",
               "refresh_hz": 120, "type": "Dynamic AMOLED 2X",
               "brightness_nits": 2600 },
  "cameras": [ … ], "battery_mah": 4000, "charging_wired_w": 25,
  "weight_g": 162, "ip_rating": "IP68", "os": "Android", "os_version": "15",
  "image_url": "…", "images": [ … ],
  "score": {
    "overall": 60.8, "performance": 88.9, "camera": 36.1,
    "battery": 54.4, "display": 63.8, "value": 59.0,
    "perf": { "index": 88.9, "percentile": 92.0, "tier": "A",
              "era": "2024-2026", "source": "geekbench" }
  },
  "verified": false,
  "source_urls": ["https://…"]
}
```

주의할 점 세 가지:

1. **`verified: false`인 레코드가 많다.** 미검증 데이터임을 사용자에게 알리는 표식이 필요하다. 숨기지 말 것.
2. **필드가 자주 비어 있다.** 구형·저가 기기는 `msrp_usd`, `ip_rating`, `score` 등이 통째로 없다. **빈 값 상태가 기본값이라고 생각하고 설계할 것.** "정보 없음"이 화면의 절반을 차지해도 깨지지 않아야 한다.
3. **`source_urls` 노출은 법적 의무다.** 데이터가 CC-BY-SA 4.0이라 "Data from TechAPI" 귀속 표기와 출처 링크가 반드시 보여야 한다. 푸터에 작게 넣든 상세 화면 하단 섹션으로 두든, 빠지면 라이선스 위반이다.

### 5. 점수 시각화 — 이건 명세다, 재량이 아니다

`overall / performance / camera / battery / display / value` 6개 값은 모두 **0–100 동일 척도**다.

**레이더(스파이더) 차트를 쓰지 마라.** 축 순서에 따라 면적이 달라 보여 값이 왜곡되고, 두 기기를 겹치면 교차 영역을 읽을 수 없다. (v1이 이걸 썼다. 답습하지 말 것.)

대신:

**단일 기기 상세**
- `overall`은 **히어로 숫자** (48px 이상, Space Grotesk). 차트 아님.
- 나머지 5개는 **미터 5줄** — 동일 램프의 트랙 위에 채움. 각 줄에 라벨과 수치를 직접 표기.
- `tier`(A/B/C…)와 `percentile`은 **뱃지**로. "상위 8%" 같은 문장이 숫자 92.0보다 잘 읽힌다.

**기기 비교 (2–4대)**
- **가로 그룹 막대.** 5개 축을 행으로, 기기를 계열(series)로.
- 기기별 색은 아래 순서로 **고정 배정**. 순위에 따라 색이 바뀌면 안 된다 — 필터를 바꿔도 같은 기기는 같은 색.

| 슬롯 | 라이트 | 다크 |
|---|---|---|
| 1 | `#2a78d6` | `#3987e5` |
| 2 | `#eb6834` | `#d95926` |
| 3 | `#1baf7a` | `#199e70` |
| 4 | `#eda100` | `#c98500` |

이 팔레트는 검증기를 돌려 통과시킨 값이다 (색각이상 인접쌍 최소 ΔE 8.4, 정상시야 19.8). **다만 라이트 모드에서 3개 색이 배경 대비 3:1 미만이므로, 막대마다 직접 라벨(기기명 + 수치)이 반드시 붙어야 한다.** 범례만으로 끝내면 안 된다. 비교 대상은 **최대 4대**까지. 그 이상은 색을 새로 만들지 말고 표로 전환.

**마크 규격**
- 막대는 얇게, 데이터 끝단만 4px 라운드, 기준선 쪽은 각지게
- 인접 막대·스택 세그먼트 사이 2px 서피스 간격
- 그리드와 축은 후퇴색(`faint`), 데이터가 주인공
- 점수 텍스트는 계열 색이 아니라 텍스트 토큰(`fg`/`fg-2`)을 쓴다. 색은 옆의 마크가 담당한다

### 6. 설계할 화면

우선순위 순. 각 화면은 **데이터 있음 / 비어 있음 / 로딩 / 오류** 네 상태를 모두 그려줘.

1. **홈** — 검색 진입, 카테고리(스마트폰·CPU·GPU·노트북), 랭킹 진입. v1은 여기에 "button1/button2/button3"이라는 이름 없는 버튼과 지도·장바구니 아이콘이 방치돼 있었다. v2 홈은 **검색과 랭킹 두 가지 일**만 한다.
2. **검색 / 목록** — 9만 건을 좁히는 화면. 브랜드·출시연도·가격대·점수 필터. 필터는 차트/목록 위 **한 줄**에 둔다. 결과 카드에는 썸네일, 이름, SoC, `overall` 점수, `tier` 뱃지.
3. **기기 상세** — §5의 점수 블록 + 스펙 표(디스플레이/카메라/배터리/충전/무게/방수) + 출처 섹션. 스펙 수치는 JetBrains Mono.
4. **비교** — 2–4대 나란히. 스펙 표는 **차이 나는 행을 강조**하고 같은 값은 후퇴시킨다.
5. **랭킹** — `score.overall` 정렬 목록. 순위 숫자, tier, percentile.
6. **AI 상담** — 채팅. 답변 안에 기기 카드가 인라인으로 박히는 형태(추천 결과를 바로 상세로 연결).
7. **온보딩** — 3단계 이내. v1은 튜토리얼을 건너뛰면 다시 볼 수 없다는 경고 다이얼로그를 띄웠다. 그런 되돌릴 수 없는 선택은 만들지 말 것.
8. **프로필/설정** — 로그인, 다크모드, 언어. v1은 다크모드를 켜면 **앱을 재시작**했다. v2는 즉시 반영.

### 7. 제약

- Flutter Material 3 기반. 커스텀 렌더링이 필요한 부분은 명시해줘.
- 한국어가 1순위 언어. **한글이 영어보다 길어지는 라벨**을 전제로 레이아웃을 잡을 것 (예: "성능" vs "Performance"는 반대지만, "배터리 충전 속도" 같은 조합은 길어진다).
- 한 손 조작. 주요 액션은 화면 하단 1/3 안에.
- 접근성: 계열이 2개 이상이면 범례는 항상 있고, 4개 이하면 직접 라벨도 함께. 색만으로 정보를 전달하지 않는다. 표 보기(table view)를 대안으로 제공.

### 8. 산출물

1. **디자인 토큰** — 위 팔레트를 Flutter `ThemeData`로 옮긴 정의 (색·타이포 스케일·간격·라운드)
2. **컴포넌트** — 기기 카드, 스펙 행, 점수 미터, tier 뱃지, 비교 막대, 필터 칩, 빈 상태, 출처 블록
3. **화면 시안** — §6의 8개 화면, 라이트/다크 양쪽
4. **근거 메모** — 주요 결정마다 왜 그렇게 했는지 2–3줄

먼저 §1–4를 읽고 **질문이 있으면 설계 전에 물어봐.** 특히 "빈 필드가 많은 레코드"와 "9만 건 탐색"을 어떻게 풀지에 대해 네 판단이 있으면 그걸 먼저 제안해줘.
