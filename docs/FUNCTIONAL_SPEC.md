# TechPicks 기능 명세서

v2.0.0 기준. 이 문서는 **앱이 실제로 무엇을 하는가**를 적는다. 화면이 어떻게
생겼는지는 `DESIGN_HANDOFF.md`, 왜 이렇게 만들었는지는 `REBUILD_PLAN.md` 에 있다.

여기 적힌 규칙은 전부 코드에 구현돼 있고 테스트가 걸려 있다. 아직 못 만든 것은
§12 에 따로 모았다.

---

## 1. 제품 정의

기기를 고를 때 **숫자 하나로 답을 준다.** 성능·카메라·화면·배터리·가성비 다섯
축의 점수를 사용자가 정한 비중으로 합쳐 TP Index 를 낸다.

핵심은 이 지수가 고정값이 아니라는 것이다. 카메라를 중요하게 보는 사람과
배터리를 중요하게 보는 사람은 같은 기기에 다른 점수를 본다.

| | |
|---|---|
| 대상 | 새 기기를 사려는 사람 |
| 플랫폼 | iOS, Android |
| 계정 | 없어도 전부 쓸 수 있다 |
| 언어 | 영어, 한국어 |

---

## 2. 용어

| 용어 | 뜻 |
|---|---|
| **TP Index** | 다섯 축을 가중 합산한 0–100 점수. 사용자 가중치를 탄다 |
| **축(axis)** | 성능·카메라·화면·배터리·가성비 |
| **가중치(weights)** | 축마다의 비중. 사용자가 바꾼다 |
| **카탈로그** | 앱에 같이 실린 큐레이션 기기 목록 (폰 10, SoC 5, 노트북 CPU 5) |
| **관심 목록(shortlist)** | 사용자가 담아둔 기기 |
| **결론(verdict)** | 관심 목록에서 지수가 가장 높은 기기 |
| **변동(movers)** | 지난 실행 대비 순위 변화 |
| **손님(guest)** | 계정 없이 쓰기로 한 상태 |

## 3. 핵심 계산 규칙

### 3.1 TP Index

```
TP Index = Σ(축 점수 × 축 가중치) / Σ(값이 있는 축의 가중치)
```

기본 가중치는 성능 .25 · 카메라 .25 · 화면 .20 · 배터리 .20 · 가성비 .10.

**값이 없는 축은 0점이 아니라 계산에서 뺀다.** 분모도 같이 줄어든다. 데이터가
덜 채워진 것과 점수가 낮은 것은 다르다. 다섯 축이 전부 비어 있으면 지수는
`null` 이고 화면에는 `—` 로 나온다.

### 3.2 랭킹 정렬

축은 다섯 개다 — TP Index · 배터리 · 카메라 · 가성비 · 가격.

- **가격만 오름차순**이다. 나머지는 내림차순
- 값이 없는 기기는 **목록에서 빼지 않고 맨 아래로 민다**. 그 기기가 목록에
  있다는 사실 자체를 사용자가 알아야 한다
- 값이 둘 다 없으면 이름순
- 막대 채움 비율은 항상 "길수록 좋음"이다. 가격은 최저가를 가득 찬 것으로 본다

### 3.3 비교 승자 판정

표는 10줄이다: TP Index · 가격 · 화면 · 칩셋 · 카메라 · 배터리 · OS · 무게 ·
두께 · 출시일.

- **수치로 비교하는 줄은 셋뿐이다** — TP Index, 가격, 배터리
- 가격은 싼 쪽이 이긴다
- 한쪽에만 값이 있으면 승자를 표시하지 않는다. 비교가 아니라 결측이다
- 화면·칩셋·카메라·OS 같은 문자열은 무엇이 나은지 데이터만으로 정할 수 없어
  표시하지 않는다
- 무게·두께·출시일은 수치지만 뺐다. 가벼운 쪽이 항상 낫다고 할 수 없다
  (배터리를 줄여 가벼운 경우가 있다)

### 3.4 이번 주 변동

- **기본 가중치 기준** TP Index 순위로만 낸다. 사용자가 슬라이더를 만질 때마다
  "이번 주 변동"이 바뀌면 그건 시간 변화가 아니라 취향 변화다
- 앱을 켤 때 지금 순위를 다음 실행용으로 남긴다 (실행당 한 번)
- 지난 순위가 없으면 빈 목록이고 섹션이 통째로 빠진다
- 최대 3줄

### 3.5 스캔 매칭

카메라가 읽은 글자를 카탈로그와 맞춘다. 원문을 그대로 보여주지 않는다.

- 확신도 **0.5 미만이면 못 찾은 것으로 본다.** 기기 이름의 절반 이상이 읽힌
  글자에 들어 있어야 한다. 더 낮추면 `Galaxy` 만 읽고 아무 삼성 폰이나 집는다
- 브랜드명도 비교에 넣는다 — 뒷면에 같이 찍혀 있다
- 소문자로 낮추고 기호는 공백으로 바꾼다. OCR 이 하이픈·점을 흘린다

## 4. 화면별 기능

### 4.1 홈

관심 목록이 비었는지에 따라 갈린다.

**비었을 때** — 안내 카드 하나(`아직 담은 기기가 없습니다` + 담기 버튼)만.
결론 카드를 보여주지 않는다.

**있을 때**
1. 큰 제목 `오늘` + 개수에 따라 달라지는 부제 (0 / 1 / 여럿)
2. **결론 카드** — 지수가 가장 높은 기기, 62px 지수 숫자, 한 문장 근거,
   5축 점수 막대, `전체 비교` / `이유 물어보기`
3. **관심 목록** — 행마다 지수·이름·가격·칩셋. 탭하면 상세.
   **스와이프 또는 길게 눌러 제거**
4. **이번 주 변동** — 최대 3줄, 오른 쪽은 파랑 `▲`, 내린 쪽은 회색 `▼`.
   탭하면 랭킹

### 4.2 랭킹

- 위쪽 카테고리 칩: `Phones` · `Processors` · `Laptops`. 셋 다 하단 탭은
  랭킹으로 유지되며 서로를 교체한다 (푸시가 아니라 교체라 뒤로 가기가 안 생긴다)
- 정렬 축 칩 5개. 바꾸면 행이 220ms 동안 새 자리로 미끄러진다
- 행: 순위 숫자(1–3위만 파랑), 이름, 활성 축의 값, 3px 막대
- 스캔 진입 — Android 는 확장 FAB, iOS 는 콘텐츠 안 버튼

### 4.3 프로세서

- `Mobile` / `Laptop` 세그먼트
- 행: 이름, sub 줄, 지수, 막대
- sub 줄은 모바일이 제조사·공정·GPU, 노트북이 제조사·코어 구성·TDP
- 지수는 TechAPI 의 `score.overall` 이다. **사용자 가중치를 타지 않는다** —
  프로세서 점수에는 카메라·화면 같은 축이 없다
- 탭해서 열 상세가 없다

### 4.4 비교

- 두 열의 머리를 탭하면 선택 시트가 열리고, 고른 기기가 그 열에 들어간다
- 아래는 §3.3 의 10줄 표
- `왜?` 를 누르면 **두 기기를 그대로 상담에 물어본다.** 한쪽이라도 비어 있으면
  버튼 자체가 없다
- 처음 열면 카탈로그 앞의 두 기기가 들어가 있다

### 4.5 선택 시트

밀어 올린 화면. 전체 기기를 지수·가격과 함께 보여준다. 고르면 §4.4 의 해당
열에 쓰고 닫힌다.

### 4.6 상세

1. 제품 사진 자리 (196px) — 사진은 아직 없다
2. 브랜드·이름·가격·지수
3. §3.3 과 같은 10줄 스펙 표
4. 5축 점수 막대
5. `관심 목록에 담기` / `담겨 있음` (상태에 따라), `비교`, `3D 보기`

카탈로그에 있으면 그걸 쓰고, 없으면 TechAPI 로 직접 받는다. 둘 다 실패하면
`불러오지 못했습니다`.

### 4.7 상담

- 씨앗 인사말 하나로 시작한다
- 입력 위에 제안 칩이 가로로 흐른다
- 보내면 **사용자 말풍선을 먼저 올리고** 답을 기다린다. 답이 오면 아래로 스크롤
- AI 답은 구조화된다 — 고른 기기 한 줄, 한 문장 근거, 4줄 표
  (TP Index / 가격 / 배터리 / 카메라), 탭하면 상세
- **모델이 카탈로그 밖의 기기를 고르면 답을 버린다.** slug 로 먼저 찾고 없으면
  이름으로 한 번 더 찾는다. 둘 다 실패하면 실패 안내
- 표시 이름은 카탈로그 쪽을 쓴다. 상세 화면 제목과 어긋나면 안 된다
- 답을 못 만들면 실패 말풍선. 화면이 멈추지 않는다

### 4.8 내 정보

- 프로필(이름·이메일·아바타), 내 기기
- **가중치 슬라이더 5개** — 움직이면 앱 전체 지수가 즉시 다시 계산된다
- 설정: 언어(즉시 반영, 재시작 없음) · 다크 모드 · 알림 · 통화
- 비밀번호 변경, 로그아웃
- 푸터에 버전과 라이선스

### 4.9 온보딩

3페인. 스와이프 또는 `다음`. 오른쪽 위 `건너뛰기`. 마지막 페인의 버튼은
`시작하기` 이고 로그인으로 간다. 한 번 끝내면 다시 나오지 않는다.

### 4.10 로그인

버튼 5개 — Google · Apple · Facebook · 이메일 · **계정 없이 둘러보기**.
푸터에 `가입` 링크.

- `계정 없이 둘러보기` 는 익명 로그인이 실패해도 들어간다. 계정 없이 비교가
  되는 게 이 앱의 전제고, Firebase 설정이 없는 빌드에서 여기가 막히면 앱에
  들어갈 방법이 하나도 없다
- 이 선택은 **기억된다.** 다음 실행에 로그인 화면을 다시 보지 않는다
- 로그아웃하면 그 표시도 같이 지운다
- `가입` 은 이메일 화면을 가입 쪽으로 연다
- Apple·Facebook 은 아직 연결 안 됨. 누르면 안내가 뜬다

### 4.11 이메일 로그인

이메일 형식과 비밀번호 길이(6자 이상)만 미리 거른다. 진짜 검증은 서버가 한다.
로그인/가입 전환은 같은 화면에서 한다.

### 4.12 스캔

전면 인수 화면. 뒷면 모델명을 읽어 §3.5 로 맞춘다. 맞으면 결과 카드가 아래에서
240ms 동안 올라오고, `기기 열기` 로 상세에 간다.

### 4.13 3D 뷰어

전면 인수 화면. 부품 칩(화면·배터리·칩셋·카메라)을 누르면 해당 부위가 강조된다.
모델 파일이 없어 와이어프레임 대역으로 그린다.

## 5. 상태와 저장

### 5.1 남는 것

| 키 | 내용 | 비고 |
|---|---|---|
| `tp_weights` | 가중치 | 깨져 있으면 기본값 |
| `shortlist_slugs` | 관심 목록 | |
| `rank_snapshot_slugs` | 지난 순위 | 변동 계산용 |
| `is_tutorial_completed` | 온보딩 완료 | **v1 키를 그대로 쓴다** |
| `browsing_as_guest` | 계정 없이 쓰기 | |
| `notifications_enabled` | 알림 설정 | 기본 켬 |

언어는 easy_localization 이 알아서 저장한다.

### 5.2 복원 규칙

- 복원은 전부 비동기다. 화면은 기본값으로 먼저 뜨고 저장값이 뒤늦게 덮는다
- **온보딩 완료 여부만 예외다.** 안 읽은 상태를 따로 두고 그동안 아무것도
  그리지 않는다. 안 그러면 앱을 켤 때마다 온보딩이 한 프레임 스쳐 지나간다
- 저장값이 깨져 있으면 종류를 가리지 않고 기본값으로 떨어진다
- 복원이 착지하기 전에 화면을 떠나도 터지지 않는다

### 5.3 저장 시점

- 가중치는 **400ms 모아서** 쓴다. 슬라이더는 끄는 동안 픽셀마다 값을 바꾸는데
  그때마다 쓰면 한 번 끌 때 백 번 가까이 쓴다. 화면은 즉시 바뀐다
- 미뤄둔 쓰기는 앱이 내려갈 때 내보낸다
- 나머지는 바뀔 때 바로 쓴다

### 5.4 안 남는 것

비교 중인 두 기기, 랭킹 축, 카테고리, 프로세서 세그먼트, 대화 내용,
스캔 상태.

## 6. 네비게이션

- 하단 탭 5개 — 홈 · 랭킹 · 비교 · 상담 · 내 정보
- 탭을 오가도 스크롤 위치와 입력이 남는다
- **밀어 올리는 화면은 한 단계뿐이다** — 상세 · 선택 시트 · 스캔 · 뷰어.
  뒤로 가면 원래 탭으로 돌아온다
- **다른 탭에서 시스템 뒤로 가기는 홈으로 온다.** 홈에서만 앱이 닫힌다
- 랭킹 탭 안의 세 카테고리는 푸시가 아니라 교체다
- 전환은 iOS 가 오른쪽 슬라이드(가장자리 스와이프 포함), Android 가
  shared axis X (300ms)

## 7. 데이터

### 7.1 출처

[TechAPI](https://github.com/GetTechAPI/TechAPI), CC-BY-SA 4.0. 출처 표기는
의무라 애셋에도 박아뒀고 화면에도 나온다.

### 7.2 카탈로그 애셋

목록 인덱스에 점수가 없고 전체 목록이 19MB 라 앱에서 그대로 못 쓴다. 빌드
시점에 큐레이션한 기기만 받아 `assets/catalog/v1.json` 으로 굽는다.

- 폰 10종 — 전부 점수와 브랜드가 있어야 한다
- 모바일 SoC 5종, 노트북 CPU 5종 — 전부 점수가 있어야 하고, CPU 는
  `segment == laptop` 이어야 한다

`dart tool/build_catalog.dart` 로 다시 만든다.

### 7.3 원격

카탈로그 밖의 기기를 상세로 열 때만 TechAPI 로 직접 간다.

| 상황 | 결과 |
|---|---|
| 404 | `NotFoundFailure` |
| 그 밖의 2xx 아님 | `ServerFailure` (상태 코드 유지) |
| 연결 실패 | `NetworkFailure` |
| JSON 아님 / 객체 아님 | `ParseFailure` |

연결 15초, 수신 30초. GitHub Pages 가 `text/plain` 으로 주는 경우도 읽는다.

실패한 카탈로그·기기 조회는 **재시도하지 않는다.** 앱에 실린 파일은 재시도해도
결과가 같고, 조용히 재시도하면 화면이 영원히 로딩으로 보인다.

### 7.4 AI 응답 계약

모델은 JSON 만 돌려줘야 한다.

```json
{"pick":"<이름>","slug":"<slug>","reason":"<한 문장>",
 "rows":[{"label":"TP Index","value":"..."}, ... 4줄]}
```

- 코드펜스를 두르거나 앞뒤에 말을 붙이는 일이 흔해 첫 `{` 부터 마지막 `}` 까지만
  잘라 읽는다
- 마크다운을 렌더링하지 않는다
- 프롬프트에 카탈로그 전체를 컨텍스트로 넣는다
- Firebase 설정이 없으면 카탈로그만으로 답하는 구현으로 떨어진다

- Apple·Facebook 은 미연결
- **Firebase 가 없어도 앱은 뜬다.** 초기화 실패를 삼키고, 인증은 네 경로 다
  조용히 실패한다. 로그인만 안 되고 랭킹·비교·상담·내 정보는 다 된다

---

## 9. 국제화

- 영어, 한국어. 언어를 바꾸면 즉시 반영된다 (v1 은 앱을 재시작했다)
- 한국어는 음역이 아니라 뜻으로 옮긴다 — `Rankings` → `2026 순위`,
  `Where this lands` → `지금의 결론`
- 온보딩·로그인 제목의 줄바꿈 위치는 두 언어가 같아야 한다
- 사용자에게 보이는 문자열은 전부 번역 파일을 거친다. 코드에 박힌 문장이 있으면
  테스트가 잡는다

## 10. 접근성

- 탭할 수 있는 것은 **전부 버튼(또는 입력창)으로 읽히고 이름이 있어야 한다.**
  맨 `GestureDetector` 는 시맨틱 트리에 탭 액션을 안 만들어서 기본 검사를
  빠져나간다
- 숫자가 많은 화면은 문장으로 읽는다 — `1위. Galaxy S25 Ultra, TP 지수 77`
- 목록 행은 각각 별개 노드다. 안 그러면 전체가 하나로 합쳐져 한 번에 읽힌다
- 입력창 이름은 **글자를 쳐도 남는다.** 힌트로만 주면 사라진다
- 새로 도착한 AI 답은 스크린 리더가 읽어준다
- 승패를 색으로만 표시하지 않는다
- 탭 타깃 최소 48dp
- 글자 크기 **1.6배까지** 레이아웃이 넘치지 않는다

## 11. 오류와 빈 상태

| 상황 | 동작 |
|---|---|
| 카탈로그를 못 읽음 | 각 화면이 빈 목록 안내. 스켈레톤을 계속 돌리지 않는다 |
| 기기를 못 불러옴 | `불러오지 못했습니다` |
| 상담이 답을 못 만듦 | 실패 말풍선. 입력은 계속 가능 |
| 관심 목록이 빔 | 안내 카드. 결론 카드를 숨긴다 |
| 지난 순위가 없음 | 변동 섹션 자체가 없다 |
| 스캔이 못 맞춤 | 결과 카드를 안 띄운다 |
| 내 기기가 카탈로그에 없음 | 이름만 보여준다 |

로딩은 **카드 반지름 그대로의 스켈레톤**이다. 가운데 스피너를 쓰지 않는다.
